# Syllabus Revision for Canvas

Create reviewable syllabus revisions without inventing course information or modifying Canvas directly.

## Required sources

Locate sources only inside the workspace the user selected. Prefer clearly named files for:

- the current syllabus;
- official institutional policies;
- official academic calendar or term dates;
- instructor-requested changes; and
- an optional institutional or departmental template.

The current syllabus and a description of the requested change are required. If dates, policies, contact information, or grading rules cannot be verified from supplied sources, mark them `[INSTRUCTOR TO COMPLETE]` rather than guessing.

## Source priority

Unless the instructor specifies otherwise, use this order:

1. supplied required institutional policies;
2. supplied official academic calendar and term dates;
3. explicit instructor instructions for this revision;
4. supplied department template;
5. the existing syllabus; and
6. general formatting preferences.

Surface conflicts for instructor review. Never silently rewrite a required policy to resolve a conflict.

## Workflow

1. Inventory the relevant files and summarize the requested changes.
2. Identify missing information, policy conflicts, inconsistent grading values, and date/weekday mismatches.
3. Produce a change log using [assets/change-log-template.md](assets/change-log-template.md).
4. Create a clean revised syllabus as a new file.
5. When Canvas output is requested, also create a semantic, Canvas-ready HTML fragment and read [references/canvas-handoff.md](references/canvas-handoff.md).
6. For accessibility review, read [references/accessibility-checklist.md](references/accessibility-checklist.md) and report unresolved issues.
7. Produce an instructor verification checklist and a separate list of items that must be changed in Canvas assignments, the calendar, modules, or other course areas.

Preserve the original. If the workspace has no output convention, create an `AI-Drafts` folder. Use versioned filenames such as `syllabus-draft-01`, `syllabus-change-log`, and `syllabus-canvas-ready`.

## Content boundaries

- Do not invent dates, URLs, office hours, contact details, grading rules, accommodations language, or institutional policy.
- Preserve the meaning of supplied required policies; distinguish exact text from plain-language explanation.
- Check whether percentage-based grading components total 100 percent.
- Use plain student-facing language without removing necessary requirements.
- Use descriptive headings and link text; do not rely on color alone.
- Avoid complex tables when headings and lists are clearer.
- Do not publish to Canvas, modify an LMS, or send announcements.
- Treat all generated files as drafts until the instructor approves them.

If the user requests a revised `.docx` or PDF and the host provides a document-specific tool, use that tool and follow its verification procedure. Otherwise provide clean HTML and Markdown drafts rather than pretending a formatted document was produced.
